# DeepFaker 项目阶段汇报（2025-10-24）

## 1. 背景与动机
- 初期目标：在 **DeepFakeBench (DFBench)** 上探索新型检测器，加强人脸伪造识别能力。
- 文献启发：调研 `docs/s1.pdf`（MUGCL，多模态传播链+不确定性对比学习）与 `docs/s2.pdf`（Assess & Guide，Dirichlet 证据融合），发现传统单一检测器难以覆盖“内容+传播+溯源”三源证据的互补性。
- 研究策略转向：构建一个面向真实社交平台的多源不确定性框架，重点回答“如何在早期传播阶段识别高风险人脸媒体，并给出可解释的风险评分”，以支撑后续策略管控。

## 2. 数据来源与采集策略
- **平台调研**：X/Twitter 需付费 API，Reddit 免费但条款限制训练用途；因此现阶段采用 Reddit **只读采集** 做行为分析，未来训练计划迁移到 YouTube、微博以及公开数据集（DFDC、FaceForensics++）。
- **采集工具链**：
  - `p2p/tools/watch_reddit_faces.py`：持续轮询子版块，下载媒体、刷新互动指标（score/评论等），并写入 `posts_status_all.csv` / `posts_status_faces.csv`。
  - `p2p/tools/filter_faces.py`（已改进）：先尝试 **RetinaFace** 检测人脸，置信度 ≥0.9 & 最短边 ≥60px；若未命中再退回调优后的 Haar cascade（`minNeighbors≥6`、`minSize=80`），显著降低风景/纹理误报。
  - `p2p/analysis/compute_face_propagation.py`：根据 `propagation_timeseries.csv` 计算传播增速、首评论延迟、若干时间窗口特征（目前 5/15/60min 窗口在旧数据上仍为空，需要依赖新采样）。
- **状态与规模**（2025-10-24 运行 9 轮后）：
  - 全量帖子 `posts_status_all.csv`：2,710 条；其中具备可用人脸裁剪的 `posts_status_faces.csv`：1,513 条（覆盖率 55.8%）。
  - 人脸子集在交互指标上显著高于全量：score 中位数 227（全量 210）、评论中位数 28（全量 27）、score>100 占比 65.3%（全量 63.6%）。
  - 平均每帖可提取人脸裁剪 1.02 张，说明“真实人脸场景”被良好捕获。

## 3. 现有流程（端到端）
1. **采集**：Watcher 过滤新近（默认 ≤6h）的帖子，下载媒体。
2. **元数据提取**：生成 `posts_status_all.csv` / `posts_status_faces.csv`，保留互动轨迹（score、upvote ratio、评论）与人脸裁剪路径。
3. **人脸检测**：通过 RetinaFace → Haar cascade 组合筛出人脸，裁剪为 256×256 PNG。
4. **传播建模**：`propagation_timeseries.csv` 累积时间序列；`face_propagation_features.csv` 计算增速、首评论延迟等指标（未来将真正命中 5/15/60 分钟窗口）。
5. **多模态检测器**：计划调用 DFBench 的多检测器对裁剪人脸进行伪造分析（当前正在修复“非人脸/未裁剪”问题）。
6. **不确定性融合**：拟采用 Dirichlet 证据模型结合注意力层，将内容 (Ĉ)、溯源 (Ŝ)、传播 (P̂) 三路特征融合，输出风险评分及置信度；超阈值触发弃权/人工审查。
7. **策略模拟**：在离线网络传播模型中模拟干预（限流、打标、拦截），评估收益-代价前沿（TODO）。

## 4. 已发现的问题与修复
- **误判风景为“人脸”**：初版 Haar cascade 在高纹理背景会输出大量假阳性（如 `reddit_1oemhrv`），导致“多检测器冲突指数与传播速度正相关”的早期结论失真。
  - 修复：引入 RetinaFace（score≥0.9 / min_size≥60），并调高 Haar 参数；后续需重跑裁剪流程以清洗旧记录。
- **采样时间过晚**：旧数据的首个快照距 `created_utc` ~9–10 小时，5/15/60 分钟窗口全部为 `NaN`。
  - 改进：Watcher 新增 `--max-post-age-hours` 与 `--max-refresh-batch`，并为每帖设定 `next_refresh_utc` 加速新帖刷新。目前已启动再采集，预计未来几个小时内的新样本能填充首小时窗口。
- **训练数据合规**：Reddit 数据仅用于分析，不会直接训练；计划使用 YouTube/微博/公开数据集进行模型训练，符合版权与隐私要求。

## 7. 风险与对策
- **检测器鲁棒性**：需在多数据集上交叉验证 RetinaFace + 多检测器 pipeline，防止 domain shift。
- **数据合规**：严格区分“监测分析”和“模型训练”数据源；输出统计时隐去个人信息。
- **系统可扩展性**：Watcher 支持多实例运行（fast lane + slow lane），避免单实例遍历数千帖子；后续考虑 Kafka/队列式架构。

## 8. 汇报要点提炼
1. **框架构想**：内容（DFBench 多检测器）+ 溯源（签名、水印、域名、证书）+ 传播（早期增速、评论动力学）三源不确定性融合，输出可解释风险评分。
2. **数据现状**：大规模 Reddit 人脸样本已就绪，互动指标高于全量；已修正误捕问题，正补采首小时数据，为不确定性建模打基础。
3. **技术进展**：Watcher、裁剪、传播特征脚本已模块化；RetinaFace 加入后极大降低误判；可在数小时内观测新帖子早期传播轨迹。
4. **下一阶段**：将 `face_propagation_features` 与多检测器分数、溯源特征对齐，实现 Dirichlet 融合；构建 OPE 策略评估，给出“误判率减半 + 自动弃权”量化证据。
